REFERENCE MAP · ACTION RECEIPT

From source text to an approved receipt, entirely in your browser.

This map describes the current implementation. The learner has not yet completed the hands-on review or learning wrap-up. It records code and mechanical checks, not learning outcomes or submission prose.

The useful boundary

Selected English text rules propose actions. Code checks quotation presence and date structure. A person checks meaning, fixes omissions and approves what may leave the workspace. The app uses no model, API, account or remote processing.

01 · Find a proposal

extractLocally

lib/local-extraction.ts

Match bounded English instruction and date patterns against the actual input. Retain exact evidence and conditions. Shared calendar syntax in lib/dates.ts recognizes common English month abbreviations without splitting the original quote. An adjacent weekday that contradicts its date becomes an unresolved source-review flag. Relative dates and uncertain date roles stay unresolved. Saved sample results are never looked up by this engine. Unlinked dates, skipped text and unsupported obligations become exact source-review entries with reasons and a stated list limit.

02 · Review and repair

ActionCard / ManualActionForm

app/receipt-workspace.tsx

Inspect evidence, correct wording, add a missed action from source, and supply dates or cutoffs. The manual form can reuse a highlighted source passage. Edits revoke approval through editAction.

03 · Check eligibility

calendarEligible

lib/receipt.ts

Calendar entries need matched action evidence, approval, date confirmation and complete date/time information. Checklist-only items can retain uncertainty. Original warnings stay in exports.

04 · Create the file

calendarText / checklistText

lib/export.ts

Inspect included actions, exclusion reasons and exact file text in app/export-preview.tsx. The preview and downloads use the same planExports eligibility rules. Create local downloads containing approved items, quotes, conditions, date corrections and proposal origins. Notice-level notes and flagged source passages remain context in both formats and never become extra tasks. Nothing is added to an external calendar automatically.

Address source flags deliberately

app/source-review-queue.tsx presents one identified flag at a time. lib/source-review.ts creates source-backed repairs and records explained user decisions. A link does not approve an action or confirm a date. Changed actions and imported decisions require rechecking. Counts cover identified flags only, never complete extraction. Decisions and original reasons remain visible in previews and exports. The trial kit in devpost/usability/ is prepared, with no participant observations claimed.

Continue a review later

lib/review-file.ts creates and opens explicit local JSON review downloads. They contain the full notice, including unapproved actions. Loading validates bounded data and exact quotations, recomputes cutoff protection and resets approvals/date confirmations. File metadata and interpretation remain unverified. A stale read cannot replace newer review changes. Nothing is saved automatically or uploaded.

The offline entry

standalone/main.tsx renders the workspace. scripts/build-static.mjs bundles code, styles, favicon and dependency licenses into release/action-receipt.html. Its policy blocks network connections. Open the file directly in a current desktop browser.

A practice to reuse

Define a visible invariant and test it. Here, “editing a date revokes approval and date confirmation” is implemented by editAction and checked in tests/receipt.test.ts. The rule engine adds another boundary: a non-temporal “provided by Student Affairs” must not turn an event date into a registration deadline. That regression lives in tests/local-extraction.test.ts.

Next-step guidance

lib/review-guide.ts derives navigation from current source decisions and export eligibility. app/review-guide.tsx points to a flag, action or preview. Clarification stays pending; calendar review is optional. Navigation changes no approvals or dates. Excluded preview items link back to their review fields. Browser focus behavior still needs hands-on verification.

Run the checks

npm test, npm run typecheck, node --experimental-strip-types scripts/smoke-local.ts and npm run build. These are mechanical checks. Human interpretation, usability and broad language coverage are separate questions.

Verification limits

Paths and symbols match the current static app. Browser interaction and the learner's observations remain pending. Historical failed API experiments do not apply to this runtime and do not establish quality. No scripts, network, analytics or external assets are needed to read this map.
