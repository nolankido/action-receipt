# Budget-driven technical and submission revision

Decision: the learner explicitly declined API credits and additional spending. Preserve Action Receipt's source/evidence/approval kernel while replacing runtime model inference with local text rules and manual correction.

## Runtime

One self-contained HTML file contains React, styles, icons, the local rule engine and its dependency licenses. It opens from a local file. No server, account, external AI service, model download, API key, credits or paid hosting is needed. The build embeds assets and blocks network connections. The existing private review site is optional; the public repository includes the runnable file.

A free hosted-model quota would preserve a service dependency and eventual limits. An on-device language model would add model downloads, hardware constraints and more verification work. Neither is needed for this proof of concept. No new paid services, purchases, Actions workflows or background jobs were added.

## Product tradeoff

The local engine recognizes selected English imperatives and explicit date patterns. It preserves exact evidence and qualifications. It does not establish full language understanding, exhaustive extraction or reliable cross-sentence reasoning. Dates in other sentences are left for manual review. Users can add missed actions from exact source text. All approval and calendar gates remain.

Saved examples stay labeled. Fresh local scanning runs on the supplied text without a sample-result lookup. Downloads preserve whether each item came from a saved example, local rules or the user.

## Rules check

They require a new working project built with the Devpost Learn Skill Pack, generated planning documents, public open-source code and a public demo video under three minutes. No runtime AI model or paid API requirement is stated. This interpretation does not replace organizer eligibility review.

## Revised completion sequence

1. Run local rule/evidence/export checks on fresh synthetic notices and produce a self-contained build. No model-access or billing gate.
2. Have the learner open the offline file, paste new text, inspect source matches, correct an omission/date, approve items and inspect both downloads. Record real observations and fix concrete issues.
3. Complete the brief Skill Pack learning wrap-up from that actual experience.
4. Record the working local app using an existing screen recorder. The learner writes and speaks their own narration. No paid editing or model service is needed.
5. Upload the video publicly to YouTube or Vimeo, check access, and keep it below three minutes. Use the public repository's runnable HTML as the judge test route.
6. The learner writes the required submission answers and exit survey. The agent may handle technical mechanics and spelling/grammar corrections. Submit only after the actual requirements are complete; record confirmation.

The learner already authorized build/public-source/submission mechanics. No extra API key setup or funding question is needed.
